### 1. 变现端现状（国内）

- 大盘：存量博弈，广告变现从「堆曝光」转向 eCPM / 填充 / 体验一起算；据行业文称 2025 国内移动广告约 6800 亿、同比约 +18%（来源偏商业稿，量级作参考）。  
- 四大主力联盟仍是底盘：穿山甲、优量汇、快手联盟、百青藤（百度），外加华为等；小媒体很少只吃一家。  
- 中小 App 更难吃到高价量：头部媒体抢预算，腰尾更多吃剩余库存 / 低价分层 / 三方 DSP 补量。  
- 广告形态：激励视频仍是现金牛；开屏/插屏 eCPM 在抬、与激励差距在收窄；工具/买变类开屏仍偏强。  

### 2. 最新变现策略模式（小媒体常见）

| 模式 | 现在怎么玩 |
|------|------------|
| 聚合 SDK | TopOn/Taku、TradPlus、GroMore、各类国内聚合；一站接 5～20+ 家，降对接成本 |
| Bidding + 瀑布流混用 | 主流：实时竞价吃高价，瀑布流兜底填填充；纯瀑布流在退 |
| 广告位组合 | 工具：开屏+插屏+激励；内容/小说短剧：激励+插屏+信息流；尽量「场景原生」少硬打断 |
| 流量分层 | 按活度/付费意愿/新老客设不同底价与频控，高价值用户给高价源 |
| 三方/尾量补量 | 四大之外挂 Sigmob、Mintegral、360、直客/小 DSP 等，专门填低价未填请求 |
| 合规与体验 | 先审后播、降违规素材；过度插屏会伤留存，反过来打买量 ROI |

公开材料里反复出现一句：Bidding 逐步取代纯瀑布流，但实操仍是「Bidding + 瀑布」混合才稳填充。

### 3. 「吃四大联盟 + 三方尾量」的小媒体，商业逻辑（公开少，行业共识）

典型产品形态：清理加速、WiFi、充电、天气、小说/短剧壳、轻工具等——产品弱、变现强、靠买量滚。

变现侧常见打法：

1. 聚合接齐四大，再挂一堆三方 SDK 吃剩量  
2. 高曝光位（开屏/插屏/激励）堆密度，用填充率换绝对收入  
3. 用聚合 A/B、分层、底价，把「便宜请求」尽量塞满  
4. 结算走联盟/聚合，部分走更快结的小渠道  

风险点：政策与平台风控、素材违规、商店下架、eCPM 被压、买量成本抬升后 ROI 很难正。

### 4. 买量策略现在大致长什么样

公开能对上的趋势：

- 投放端：巨量 / 广点通（腾讯广告）仍是主仓；目标从浅层转化更多切到变现 ROI / 七日变现 ROI 一类深度目标（平台也在收紧部分 ROI 目标用法）。  
- 混变：尤其小游戏——IAA+IAP 混变仍是增长点；纯广告回收产品更卷首日/24h ROI。  
- 出价与素材：素材更新频率高；基建量（计划/素材数）堆起来才容易起量。  
- 小媒体/工具买变逻辑（行业常见，非单篇权威）：  
  - 按首日广告回收 / D0～D3 ROI 控成本  
  - 量从联盟高价位时段、人群包、看后效再扩  
  - 变现侧 eCPM 一掉，买量立刻砍计划或降出价  
  - 渠道与变现同生态时（字节买量↔穿山甲变现、腾讯买量↔优量汇）更容易打通数据与优化  

CBNData 也提到：中小 App 拿头部高价库存更难，更要拼广告形态、场景、用户分层，否则只会变成「高买量成本 + 低变现」双杀。

### 【助手答复正文】

继续调研结论（免 Key）：国内小媒体变现已从「接一家联盟」变成「聚合吃价差 + 尾量兜底」，买量则从「便宜量」变成「买变一体、按 ROI 模型控盘」。

### 一、变现端现状：谁在供货、谁在吃剩

上游（需求/预算）  
穿山甲公开口径：网盟消耗仍在涨，穿山甲增速高于大盘；千川、UG、AI 类等预算抬升，会溢到联盟侧。  
四大底盘：穿山甲、优量汇、快手、百青藤（+华为等）。  
小媒体位置：头部 App 吃高价；腰尾更多吃低价层 + 未填请求 + 三方/ADX 补量——这就是口语里的「吃尾量」。

中间层  
GroMore / TopOn·Taku / TradPlus / 各类国内聚合：一站接多家，Bidding + 瀑布流混跑；部分还有自有 ADX 补长尾。

下游产品形态（典型吃尾量玩家）  
清理/加速/WiFi/充电等工具、免费小说、短剧壳、轻休闲——产品弱、广告场景密、靠买量滚。

### 二、最新变现策略模式（可落地）

1. 技术架构：Bidding 为主，瀑布兜底  

- Bidding：实时出价，减超时、提填充（GroMore 称填充常可到 90%+，收益较纯瀑布可有几个到十几百分点）  
- 瀑布：5～8 家、多层底价交叉，专吃「Bidding 没吃满」的请求  
- 实务：先保证填充 ≥90%，再抬 eCPM（只抬底价会把利用率打到 30% 档，ARPDAU 反而掉）

2. 分层吃价差（尾量逻辑的技术表达）  
同一家联盟拆多个代码位：高底价层抢头部 offer，低底价/无底价层吃剩量；多家交叉排序，避免「A 的尾价挡住 B 的头价」。

3. 广告位组合  

| 品类 | 常见组合 |
|------|----------|
| 工具买变 | 开屏 + 插屏 + 激励（开屏 eCPM 仍偏强） |
| 小说/短剧 | 激励解锁剧集/章节 + 插屏 + 信息流 |
| 小游戏 IAA | 激励为主，插屏/开屏补 |

短剧侧穿山甲内容：免费短剧只允许激励解锁，不让付费解锁剧集（平台规则，以当期为准）。

4. 流量分组  
新客密瀑布保价、老客稀一点保体验；高活/高互动用户给更高底价层——和买量 ROI 回传打通。

5. 三方/尾量补量  
四大之外：Sigmob、Mintegral、360、聚合自有 ADX 等，专填低价未填；公开材料少写「吃尾量」黑话，但瀑布最底层 + 多 DSP = 同一件事。

### 三、买量策略现在怎么玩（变现端 App）

核心公式：  
单用户广告毛收入 ≈ IPU × eCPM / 1000，能否跑通看 LTV ≥ CAC（还要扣奖励、核减、异常量、账期）。

投放侧主流打法：

1. 深度目标：广告变现 ROI / 24h ROI（抖小 IAA 几乎标配）；系数别定太高，否则不起量。  
2. 基建堆量：账户×项目×计划×素材矩阵；日耗越高，日均新建计划越多（官方有分档建议）。  
3. 生态闭环：字节买量 ↔ 穿山甲变现、腾讯买量 ↔ 优量汇，数据回传和优化更顺。  
4. 混变：小游戏 IAA+IAP 仍是增长点；纯广告工具更卷 D0～D3 回收。  
5. 波动排查顺序：先查变现（填充/eCPM/场景），再查产品留存，最后才怪买量——「买变一体」是现在的口头禅。

小媒体/工具买变的经营现实（公开少，行业共识）：

- 多包、多马甲、多素材并行测  
- eCPM 一掉立刻砍计划或降出价  
- 靠高广告频次抬 IPU；过密会伤留存，反过来打 ROI  
- 账期与核减会卡现金流，比「账面 ROI」更致命  

### 四、买变闭环结构（文字版，飞书可画流程图）

## 轮次 D：单用户广告收入怎么算

### 【用户原文】

怎么计算单用户的广告收入，是离线计算还是实时计算的

### 【助手答复正文】

结论：行业里几乎都是「实时预估 + 离线结算」两套账；单用户广告收入很少只靠一种方式算准。

### 常用怎么算

最简模型：

单用户广告毛收入 ≈ IPU × eCPM ÷ 1000

- IPU：该用户广告展示次数（激励/插屏/开屏等合计）  
- eCPM：千次展示收入（分广告位、分联盟、分时段会差很多）

经营上还会看：

| 指标 | 含义 | 常用粒度 |
|------|------|----------|
| ARPDAU | 日活人均广告收入 | 日 |
| LTV（广告） | 用户生命周期累计广告收入 | D0/D1/D3/D7… |
| ROI | 广告 LTV ÷ 获客成本 | 常看 D0/24h、D7 |

更完整一点还会扣：奖励成本、平台核减、异常量、分成后净收入。

### 实时还是离线？——混合

用户看广告  
→ SDK 回调：展示/点击（近实时）  
→ ① 实时/准实时：用「预估 eCPM」或 Bidding 返回价 × 展示 → 算预估 LTV、控买量出价、看板  
→ ② 离线（T+1 或更晚）：联盟/聚合报表 API 或账单 → 真实结算收入，对账、核减、财务  

| 类型 | 算什么 | 时效 | 用途 |
|------|--------|------|------|
| 实时/准实时 | 展示事件 × 当次竞价价/缓存预估价 | 秒～分钟～小时 | 投放 ROI、熔断、分层实验 |
| 离线 | 官方结算、对账后收入分摊到用户/广告位 | 通常 T+1，有的更慢 | 财务、真实 ROI、调瀑布流 |

聚合侧（如 GroMore）会宣传实时 CPM 回传、小时级 ROI——那是给买变闭环用的预估值；和联盟月结账单往往仍有偏差，需要离线校准。

### 单用户维度怎么落到人

1. 设备/账号 ID 关联每次展示（广告位、联盟、是否填充成功）  
2. 实时路径：展示时带上 Bidding 价或分层预估价 → 累加到该用户当日/生命周期预估收入  
3. 离线路径：用报表总收入按展示量、eCPM 权重或广告位回摊到用户（精确分摊很难 100% 对齐）  
4. 买量侧用激活后 24h / 首日 ROI 等窗口，用的多半是回传的预估变现，不是等财务结完再投  

所以：

- 控投放、看盘 → 偏实时预估  
- 算真赚多少、调长期策略 → 偏离线结算  
- 成熟团队两套并行，定期看预估 vs 结算偏差  

### 实务注意

- 只有展示回调、没有可靠单价 → 只能先算 IPU，收入要等报表  
- 无底价层、手动上传报表 → 实时更虚，更依赖离线  
- 「单用户广告收入」对外口径要写清：是预估毛收还是结算净收

## 轮次 E：质疑实时策略与熔断风险

### 【用户原文】

你说的这一套东西是实时可行的吗，如果用实时价值做策略调整，很有可能模型跑偏，并且触发熔断机制，导致亏损

### 【助手答复正文】

你的担心是对的：只拿「实时预估价值」直接调策略、直接熔断，很容易跑偏，甚至把本来能赚的计划熔死，或该停的停晚了导致亏损。

实时可行，但不能当唯一真理；成熟做法是「实时只做弱干预，离线校准后再强决策」。

### 为什么实时容易带偏

| 风险 | 发生什么 |
|------|----------|
| 预估 ≠ 结算 | Bidding 价、缓存价、排序价和最终核减后收入常差一截 |
| 样本噪声 | 新计划/新素材前几小时量少，eCPM、IPU 方差极大 |
| 结构性偏差 | 高峰时段 eCPM 高、低谷低；地域/机型分布一变，实时 LTV 就飘 |
| 回传延迟与丢数 | 展示回调晚到、漏报，ROI 一时虚高一时虚低 |
| 反馈环 | 实时 ROI 偏低 → 降价/关停 → 量结构变差 → 更难看 → 错误熔断 |

所以：实时适合「感知」和「限幅」；不适合「全权裁决」。

### 更稳的用法（行业常见分层）

L0 实时（秒～分钟） → 只防极端事故，不调主模型  
L1 准实时（小时～半日）→ 小步调参、限流，带冷却时间  
L2 离线（T+1 / 滚动窗口）→ 真正改出价系数、瀑布、预算  

L0 熔断（可以实时，但条件要狠、要钝）  
只挡「明显异常」，例如：

- 单价异常（eCPM 相对基线暴跌且持续 N 分钟）  
- 作弊/异常量暴增  
- 填充率塌到不可用  
- 单计划消耗失控  

并加：冷却期、最小样本、连续触发次数、人工/二级确认，避免抖一下就全关。

L1 策略微调（准实时）  
用滚动窗口（如近 3h / 6h，且展示 ≥ 某阈值）看预估 ROI 相对历史偏差，只做：

- 限速、降预算上限、暂停差计划  
- 不大幅改 ROI 目标系数、不重训主模型  

L2 主策略（离线校准后）  
用结算/报表校准后的收入，再改：

- 出价系数、人群、素材基建  
- 瀑布底价、分层  
- 产品广告频控  

并定期算：预估收入 / 结算收入的偏差系数，用来校正实时看板（有的团队直接乘一个 settle_factor）。

### 怎么避免「熔断导致亏」或「该熔不熔」

1. 双阈值 + 迟滞：跌破 A 才告警，跌破 B 才熔断；恢复要高于 A 才重开（防抖动）。  
2. 最小样本量：未满 X 展示 / Y 转化，禁止熔断和调价。  
3. 对照基线：跟「同时段历史」或「对照组计划」比，不跟绝对 ROI 死磕。  
4. 熔断分级：先缩预算 30% → 再停差计划 → 最后停产品级；不要一刀切。  
5. 预估只进风控，结算进财务与主模型：主 ROI 模型用校准后标签训练/评估。  
6. 回放验证：用历史日志模拟「若当时用实时熔断会怎样」，再上线规则。  

### 直接回答两句

- 「这一套实时可行吗？」  
  部分可行：实时做监控、异常熔断、限幅；主策略和模型更新应准实时/离线。  

- 「用实时价值调策略会不会跑偏、乱熔断亏钱？」  
  会，若实时值直接驱动强决策。  
  正确姿势是：实时弱干预 + 样本门禁 + 迟滞熔断 + 离线校准纠偏。

## 轮次 F：要弱算法、可落地的业内通用策略

### 【用户原文】

你给我一个业内普遍适用且可以落地的策略方案，不要强算法的，实际上很多中小型公司的算法根本跑不动，因为数据模型支撑不够

### 【助手答复正文】

结论先说：中小团队别搞「强算法实时最优」，用规则 + 分层看板 + 固定复盘节奏就能跑。下面是一套业内常见、可直接落地的买变经营方案（偏工具/内容 IAA 都通用）。

### 1. 目标与原则（先定死）

唯一经营目标：在可接受风险下，让校准后的回收覆盖获客成本，并保住量级。

三条铁律：

1. 先填满，再抬价（填充率优先于追 eCPM）  
2. 实时只刹车，离线才换挡（实时不改主策略）  
3. 没样本不动刀（量不够禁止调价/熔断）  

不追求模型最优，追求少犯错、能复盘、人能执行。

### 2. 组织与分工（最小配置）

| 角色 | 职责 | 节奏 |
|------|------|------|
| 投放 | 基建、出价、关停计划 | 日更 / 日内盯异常 |
| 变现 | 聚合分层、广告位、频控 | 每周大调，每日小看 |
| 产品/运营 | 场景、激励、留存 | 周迭代 |
| 数据（可兼） | 对账、偏差系数、看板 | 日对账 |

一个人兼多职也行，但投放和变现的复盘会必须分开记问题归属，避免互相甩锅。

### 3. 两套账（必须建，很简单）

| 账本 | 数据来源 | 用途 |
|------|----------|------|
| A. 预估账 | SDK 展示 + Bidding/分层预估价 | 盯盘、弱熔断 |
| B. 结算账 | 联盟/聚合 T+1 报表（可先手工导） | 改出价、改瀑布、算真亏真赚 |

每天算一个数（Excel 就行）：

偏差系数 δ = 昨日结算收入 ÷ 昨日预估收入  
（滚动 7 日中位数更稳）

看板展示：预估 ROI × δ ≈ 校准 ROI。  
主决策只看校准 ROI；预估只用于「会不会炸」。

### 4. 核心指标（只盯这 8 个）

变现：填充率、eCPM、IPU（或人均展示）、ARPDAU  
买量：CAC（或激活成本）、消耗、量级  
闭环：D0/D1 校准 ROI、D3/D7 校准 ROI（能拆到就拆）

中小团队先做到「计划/渠道 × 日」，不要一上来做人×小时精细模型。

### 5. 变现策略（可落地配置）

5.1 接入结构（标准件）

- 聚合 1 套（GroMore / TopOn 等任选熟悉的）  
- 国内优先：穿山甲、优量汇、快手、百度；再加 1～2 家三方兜底  
- 每个主广告位：Bidding + 多层瀑布 + 无底价兜底  

5.2 瀑布冷启动（规则版）

1. 先通跑 2～3 天，每层展示尽量 ≥2000 再调  
2. 层数：DAU 小就少层（每平台 2～4 层）；DAU 大再加密  
3. 无底价层必须有，保填充 ≥90%  
4. 调价顺序：  
   - 填充 <90% → 先降底价/加兜底，禁止猛抬价  
   - 填充稳了 → 再小幅抬高价层（一次调一层，观察 1～2 天）  

5.3 广告位与频控（产品规则）

| 类型 | 建议 |
|------|------|
| 开屏 | 启动有；冷启动期可略密，稳定后降频 |
| 插屏 | 关键节点，设最小间隔（如 30～60s）和日上限 |
| 激励 | 用户主动触发；奖励成本计入毛利 |

周检查：留存掉了优先减插屏/开屏，不要先砍激励（激励通常更健康）。

5.4 变现周节奏

- 每日 15 分钟：填充、ARPDAU、异常报错  
- 每周 1 次：按收益占比调各平台层数权重；砍长期无量层  
- 双周 1 次：A/B 只测一个变量（例如多一层高价 or 降插屏频次）  

### 6. 买量策略（无算法版）

6.1 投放结构（基建规则）

- 账户/项目/计划/素材保持「能起量的最小矩阵」  
- 新素材计划占比约 15%～20%，避免全是老素材挤死  
- ROI 目标系数：不超过你真实考核的约 20% 缓冲内（过高不起量）  

6.2 看数口径（定死一个）

建议中小团队统一：

- 日常盯盘：激活后 24h 校准 ROI（或你们财务认的 D0）  
- 周决策：再看 D3/D7 是否能补回来  

口径变来变去 = 策略一定乱。

6.3 计划生命周期（人工规则）

对每个计划/广告组，按日判定（示例阈值可按你们改）：

| 状态 | 条件（示例） | 动作 |
|------|--------------|------|
| 冷启动 | 消耗 < 门槛或转化 < N | 只观察，不熔断 |
| 健康 | 校准 ROI ≥ 目标，量稳定 | 保留，可小幅放预算 |
| 观察 | 校准 ROI 在目标 ±15% | 不动或微调节 |
| 收缩 | 连续 2 日低于目标且过样本 | 降预算 30%～50% |
| 关停 | 连续 3 日明显亏且过样本 | 关计划，素材进黑名单观察 |

禁止：用小时预估 ROI 直接大改出价系数。

6.4 买量日节奏

- 上午：看昨日结算/校准，决定今日预算总盘  
- 下午：只处理异常消耗、素材审核、起量失败  
- 晚上：不改大策略（避免夜盘噪声）  

### 7. 熔断方案（防跑偏、防乱停）

7.1 实时（L0）——只挡事故

触发需同时满足：

1. 时间窗口 ≥ 30～60 分钟  
2. 消耗或展示 ≥ 最小样本  
3. 连续 2 个窗口异常  

异常示例（选 2～3 条即可）：

- 填充率相对近 7 日同时段跌超 30%  
- 预估 eCPM 相对基线暴跌且持续  
- 单计划消耗速度 > 日预算的不合理倍数  
- 明显异常点击/设备特征（有风控再用）  

动作分级：告警 → 限速/砍预算 30% → 停该计划（不是停全账户）  
恢复：指标回到安全区并再观察 1 个窗口；用迟滞，避免抖开关。

7.2 准实时（L1）——小时级弱干预

- 用滚动 3～6 小时预估 × δ  
- 只做：限预算、暂停尾部计划  
- 冷却：同一对象 4～6 小时内不重复大动作  

7.3 离线（L2）——真正换挡

- T+1 结算对账后，才改：ROI 系数、人群、总预算、瀑布底价  
- 大改必须写一句话原因 + 预期观察期（默认 48h）  

### 8. 一张「每日作战表」（Excel 就能跑）

每行一个「计划 or 渠道」：

消耗 | 激活 | CAC | 预估广告收入 | δ | 校准收入 | 校准 ROI | 填充率 | 动作

每日负责人只填动作：放 / 持 / 缩 / 停。  
周会只复盘：动作对不对、δ 稳不稳、填充有没有被牺牲。

### 9. 30 天落地路径

| 周 | 做什么 |
|----|--------|
| 第 1 周 | 聚合接齐 + 填充≥90%；建预估/结算两套表；定 ROI 口径 |
| 第 2 周 | 定计划关停规则 + L0 熔断；停止「拍脑袋抬底价」 |
| 第 3 周 | 稳定 δ；开始按周调瀑布；买量按健康/收缩/关停执行 |
| 第 4 周 | 减广告频次保留存；只做单变量 A/B；形成周报模板 |

### 10. 明确不做什么（中小团队省命）

- 不上实时强策略、不搞复杂用户价值模型  
- 不为追 eCPM 把填充打穿  
- 不在样本不足时熔断/改系数  
- 不同一天又改买量又大改瀑布（变量搅在一起无法归因）  

一句话：用结算账做主舵、预估账做刹车、瀑布保填充、计划用规则关停、每周只动一个大变量——这就是中小公司普遍跑得动、且不容易被实时噪声带进沟里的方案。

助手当时还提出可继续给：① 每日计划作战表 ② 瀑布流配置检查清单。

## 轮次 G：要汇报级可落地材料（防线上崩盘）

### 【用户原文】

可以的，你需要给我真实可落地的东西，我可是要汇报的，出了问题线上崩了会有大问题的

### 【助手交付说明】

已按「可汇报、可上线、可回滚」落地，产物如下。

产物清单：

| 文件 | 用途 |
|------|------|
| docs/IAA买变经营作战手册-v0.1.md | 汇报主文档：口径、状态机、L0/L1/L2、红线、门禁、口头稿 |
| docs/templates/每日计划作战表-模板.csv | 投放每日表（含示例行） |
| docs/templates/瀑布流配置检查清单-模板.csv | 变现每日/周检表 |
| docs/templates/参数与上线门禁-签字表.csv | 参数定稿 + 8 条上线门禁签字 |

汇报时请强调的安全点（防背锅）：

1. 默认阈值只是保守起点，必须用近 14 日回放改成你们的数后再上线。  
2. 强制三阶段：只观测 → 半自动（人确认）→ 有限自动；门禁没勾完禁止跳级。  
3. L0 最多停到「单个计划」，禁止自动停整账户。  
4. 样本未达标禁止缩/停；实时不做主策略。  
5. 任何缩/停/瀑布大改必须写回滚方式。  

汇报前还差的动作：打开签字表，把 P01～P14 填成实数，并完成「近 14 日规则回放」。没有这一步，不要对领导承诺「已经可自动熔断」。

### 【作战手册核心明细】（从交付文档展开，便于飞书粘贴）

手册定位：规则经营，不依赖强算法；实时只刹车，离线才换挡；宁可少赚，不可误熔断把盘打崩。

0. 汇报一页纸

| 原则 | 落地动作 |
|------|----------|
| 两套账 | 预估账盯盘；结算账做主决策 |
| 三层干预 | L0 事故熔断 → L1 弱限速 → L2 次日换挡 |
| 样本门禁 | 没到最小样本，禁止关停/改价/改系数 |
| 单变量 | 同一天不既大改买量又大改瀑布 |
| 可回滚 | 任何上线改动必须有回滚步骤与责任人 |

上线顺序（强制）：

1. 只观测 3～7 天（告警，不自动动作）  
2. 半自动：系统/表建议，人确认后执行  
3. 有限自动：仅 L0 限速/单计划暂停（不得全账户一键停）  
4. 未满足门禁，禁止进入下一阶段  

1. 角色与责任

| 角色 | 职责 | 可执行动作 | 禁止越权 |
|------|------|------------|----------|
| 投放负责人 | 计划健康度、预算、关停 | 降预算/暂停计划/换素材 | 不得改瀑布底价 |
| 变现负责人 | 填充、分层、广告位频控 | 调层/加兜底/降频 | 不得改 ROI 出价系数 |
| 数据负责人（可兼） | δ 对账、口径、看板 | 发布口径变更（需双人确认） | 不得当日改口径又让投放按新口径熔断 |
| 值班人 | 异常响应 | 执行 L0 分级动作 | 不得跳级「全停」 |

变更双人制（建议）：涉及「总预算 −30% 以上 / 关停消耗 Top3 计划 / 瀑布大改 / 频控大改」→ 投放+变现各一人确认。

2. 口径字典

| 名词 | 定义（手册默认） | 备注 |
|------|-------------------|------|
| 预估广告收入 | 展示事件 × 当次可用单价（Bidding 返回价或分层预估价） | 仅盯盘 |
| 结算广告收入 | 联盟/聚合报表确认收入（T+1） | 主决策 |
| 偏差系数 δ | 近 7 日「结算收入÷预估收入」的中位数 | 每日更新；异常日剔除 |
| 校准收入 | 预估收入 × δ | 用于校准 ROI |
| 校准 ROI（D0/24h） | 校准广告收入 ÷ 对应获客成本（同一归因窗口） | 主盯指标 |
| 填充率 | 有填充的请求 ÷ 广告请求 | 主广告位分别看 |
| 最小样本（计划日） | 消耗 ≥ X 元 且 转化/激活 ≥ N 个 | 上线前必须填实数 |
| 最小样本（熔断窗） | 窗口消耗 ≥ Y 元 或 展示 ≥ M 次 | 见参数表 |

归因窗口默认建议：买量看数 = 激活后 24h；周决策补充看 D3/D7。

3. 参数表（保守默认起点，须回放后改）

| 参数ID | 参数名 | 保守默认起点 |
|--------|--------|--------------|
| P01 | 目标校准 ROI（24h） | 1.0（打平） |
| P02 | 健康区间 | 目标 ±15% |
| P03 | 计划日最小消耗 X | 建议按近14日回放填写 |
| P04 | 计划日最小转化 N | ≥20 |
| P05 | 熔断窗时长 | 60 分钟 |
| P06 | 熔断窗最小消耗 Y | ≥200 元 |
| P07 | 熔断窗最小展示 M | ≥2000 |
| P08 | 填充率告警线 | 相对近7日同时段 −20% |
| P09 | 填充率熔断线 | 相对近7日同时段 −35%，且绝对值 <85% |
| P10 | 单计划消耗过速 | 1 小时消耗 > 日预算 40% |
| P11 | 冷却时间 | 同一对象 6 小时内不重复强动作 |
| P12 | 恢复迟滞 | 恢复须连续 2 个窗口回到安全区 |
| P13 | δ 告警 | δ 日波动相对7日中位 >25% |
| P14 | 主广告位填充底线 | ≥90%（日） |

回放验收：近 14 日模拟误熔断次数、漏熔断亏损，两项都要有业务可接受结论，否则只停留在「只观测」。

4. 每日计划作战表字段

日期、产品/包名、渠道、账户ID、计划ID、日预算、当日消耗、激活/转化数、CAC、预估广告收入、δ、校准收入、校准ROI_24h、样本是否达标、状态、建议动作、是否执行、执行人、回滚方式、备注

状态机：冷启动 → 健康/观察 → 收缩 → 关停候选 → 关停；L0 事故动作单独记录。

动作红线：

1. 样本未达标：禁止缩/停（L0 除外）  
2. 同一计划：一日最多一次强动作  
3. 禁止用小时预估 ROI 改出价系数  
4. 禁止一键暂停整账户（除非 P0 且负责人批准）  
5. 执行缩/停必须写回滚方式  

5. 瀑布流每日快检 Pass/Fail

检查开屏/插屏/激励填充、报错超时、ARPDAU、δ；Fail 时只允许弱动作（加兜底、降最高底价一层等），先救填充不抬价。

周检：每周固定一次；当天买量只允许持/弱缩；一次只改一个主变量；观察期默认 48h。

6. L0 触发须同时满足

1. 窗口时长 ≥ P05  
2. 样本达标  
3. 连续 2 个窗口异常  
4. 未处于冷却期  

动作阶梯：告警 → 限速（预算−30%）→ 暂停该计划；禁止跳级停账户。

7. 上线门禁（8 条，未全部勾选禁止有限自动）

1. 口径字典已定稿并同步  
2. 参数表 P01～P14 已填实数  
3. 近 14 日规则回放已做  
4. 作战表与清单已有值班  
5. L0 仅单计划级，无全账户自动停  
6. 只观测阶段已跑满约定天数  
7. 回滚演练做过一次  
8. 事故升级路径明确  

8. 给汇报人的口头稿

我们不靠复杂算法实时调价，而用「结算账做主舵、预估账做刹车」。  
线上安全靠四件事：样本门禁、分级熔断且只动到计划级、单变量变更、所有动作可回滚。  
先只观测与半自动，回放通过再谈有限自动；宁可慢，也不在噪声下把盘熔停。
